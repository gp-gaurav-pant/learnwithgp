# learnwithgp

LangChain Academy assignments and experiments, built as Jupyter notebooks.

Everything runs against a **self-hosted LLM** (vLLM serving Qwen2.5-32B-Instruct-AWQ)
rather than the OpenAI API, so the notebooks work offline apart from web search and
tracing.

## Notebooks

| Notebook | What it does | Key concepts |
|---|---|---|
| [`notebooks/food_agent.ipynb`](notebooks/food_agent.ipynb) | Personal chef assistant — takes an ingredient list, searches for a recipe, and answers follow-up questions | `create_agent`, tool calling, `InMemorySaver` checkpointer for conversation memory |

## Stack

- **Python 3.12**, managed with [uv](https://docs.astral.sh/uv/)
- **LangChain 1.3** / **LangGraph 1.2** — `langchain.agents.create_agent`
- **vLLM** serving `qwen2.5:32b` over an OpenAI-compatible API
- **Tavily** for web search
- **LangSmith** for tracing
- **JupyterLab** with LSP autocompletion and ruff

## Setup

### 1. Install dependencies

```bash
uv sync
```

### 2. Configure environment

```bash
cp env.sample .env
```

Then fill in your real keys:

| Variable | Purpose |
|---|---|
| `TAVILY_API_KEY` | Web search — get one at [tavily.com](https://tavily.com) |
| `LANGSMITH_API_KEY` | Tracing — get one at [smith.langchain.com](https://smith.langchain.com) |
| `LANGSMITH_PROJECT` | Project name traces are grouped under |
| `LANGSMITH_TRACING` | `true` to record traces, `false` to disable |
| `LOCAL_LLM_URL` | vLLM endpoint, e.g. `http://localhost:8088/v1` |

### 3. Enable output stripping

Notebook outputs are stripped from git via an `nbstripout` clean filter. The filter lives
in `.git/config`, which does **not** survive a clone, so run this once after cloning:

```bash
uv run nbstripout --install --attributes .gitattributes
```

Your working copy keeps its outputs (so results stay visible in JupyterLab); only what
git stores is code-only.

### 4. Start JupyterLab

```bash
uv run jupyter lab
```

## Running the local LLM

The notebooks expect an OpenAI-compatible endpoint at `LOCAL_LLM_URL`. Example using
Docker:

```bash
docker run --runtime nvidia --gpus all --ipc host \
  -p 8088:8000 \
  -v /path/to/huggingface:/models \
  vllm/vllm-openai:latest \
  --model /models/hub/models--Qwen--Qwen2.5-32B-Instruct-AWQ/snapshots/<snapshot> \
  --served-model-name qwen2.5:32b \
  --quantization awq_marlin \
  --dtype half \
  --max-model-len 24000 \
  --gpu-memory-utilization 0.85 \
  --trust-remote-code \
  --enable-auto-tool-choice \
  --tool-call-parser hermes
```

**`--enable-auto-tool-choice` and `--tool-call-parser hermes` are required.** Without
them vLLM serves chat completions fine but rejects every tool call with:

```
400 - "auto" tool choice requires --enable-auto-tool-choice and --tool-call-parser to be set
```

`hermes` is the correct parser for Qwen2.5. Note the port mapping: vLLM listens on 8000
inside the container, published as **8088** on the host — `LOCAL_LLM_URL` must use the
host port.

Verify the server is up:

```bash
curl http://localhost:8088/v1/models
```

## Connecting a notebook to the local model

`create_agent` has no `base_url` / `api_key` of its own — build a `ChatOpenAI` pointed at
vLLM and hand that object over:

```python
llm = ChatOpenAI(
    model_name="qwen2.5:32b",             # must match --served-model-name
    base_url=os.getenv("LOCAL_LLM_URL"),
    api_key="NA",                         # vLLM ignores it, the client requires one
)

agent = create_agent(
    model=llm,
    tools=[...],
    system_prompt="...",
    checkpointer=InMemorySaver(),         # memory belongs on the agent, not the model
)
```

Reuse a `thread_id` across calls so follow-up questions keep their context:

```python
config = {"configurable": {"thread_id": "chef-1"}}
response = agent.invoke({"messages": [user_message]}, config=config)
print(response["messages"][-1].content)   # invoke returns a state dict, not a message
```

## Gotchas

- **Editing `.env` does not affect a running kernel.** `load_dotenv(override=True)` only
  reads the file when it executes, so restart the kernel or re-run the imports cell after
  changing any variable.
- **Import `pprint` before using it.** Without the import, IPython's automagic silently
  resolves `pprint(x)` to the `%pprint` line magic, which toggles pretty-printing instead
  of printing anything.
- **Unknown `ChatOpenAI` kwargs are swallowed into `model_kwargs`** and forwarded to the
  API, where they fail at request time. A `WARNING! <name> is not default parameter`
  message means the argument is on the wrong object.

## Repo conventions

- Notebook outputs are stripped from git (see setup step 3).
- `.env` is gitignored; `env.sample` documents the required variables.
- `.ipynb_checkpoints/` and `.virtual_documents/` are generated by Jupyter and ignored.
- `uv.lock` and `.python-version` are committed for reproducible installs.
